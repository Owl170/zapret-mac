# ZapretMac

Текущая версия: **1.1.6**.

Локальный TCP-обход DPI для macOS и экспериментальный режим голоса Discord. Установщик автоматически подбирает TCP-стратегию и включает автозапуск. Управление выполняется через service.command.

[Скачать последний релиз](https://github.com/Owl170/zapret-mac/releases/latest) · [Инструкция по голосу Discord](VOICE.md) · [Проверки macOS](https://github.com/Owl170/zapret-mac/actions/workflows/macos-check.yml) · [Аудит кода](AUDIT.md)

Пакет рассчитан на **macOS 12+**, Apple Silicon и Intel. Нужны Apple Command Line Tools и Python 3.9+ из этих инструментов. Homebrew, внешний сервер и виртуальная машина не нужны. Универсальный бинарник собирается из вложенных исходников `tpws` проекта [bol-van/zapret](https://github.com/bol-van/zapret). Списки и UDP-фейк взяты из [Flowseal 1.10.3](https://github.com/Flowseal/zapret-discord-youtube/releases/tag/1.10.3); это самостоятельный порт, а не официальный выпуск Flowseal.

Полного соответствия Windows-версии нет: TCP обслуживает `tpws`, голосовой UDP — отдельный relay. UDP-игровые стратегии, QUIC-фейки, подмена TCP sequence и `badsum` не перенесены. Ограничения пакетного движка описаны в [документации upstream](https://github.com/bol-van/zapret/blob/master/docs/bsd.en.md#macos). Локальные проверки TCP/PF/UDP не подтверждают обход конкретного провайдера или двусторонний звук Discord.

## Установка

1. Откройте [Releases](https://github.com/Owl170/zapret-mac/releases/latest), скачайте из **Assets** архив `ZapretMac-<версия>.zip` и распакуйте его на Mac.
2. Откройте **install.command**. Если macOS предложит Command Line Tools, завершите их установку и повторите запуск. Введите пароль администратора.
3. Дождитесь сборки и автоподбора. Программа переберёт TCP-профили, повторно проверит подходящий профиль, сохранит его и включит обход. Это может занять несколько минут.
4. Полностью закройте Discord через **⌘Q** и откройте снова; перезапустите браузер. Проверьте Discord и YouTube.

**Автозапуск включён по умолчанию.** После перезагрузки Mac обход запускается самостоятельно. Если вы отключите автозапуск в меню, последующие обновления сохранят этот выбор.

Если Finder не запускает `.command`, выполните в Terminal из распакованной папки:

```bash
cd "$HOME/Downloads/ZapretMac"
bash install.command
bash service.command
```

Исправьте путь под вашу папку. Глобально отключать Gatekeeper или SIP не требуется.

### Обновление установленной программы

Начиная с 1.1.5 откройте **service.command → 8 — «Обновить ZapretMac»**. Программа проверяет последний стабильный релиз именно **Owl170/zapret-mac**, загружает ZIP и SHA-256 с GitHub, проверяет манифест всех файлов, собирает Universal-движок и устанавливает обновление с сохранением настроек и пользовательских списков. Дождитесь сборки и автоподбора; после обновления меню перезапустится с новым кодом. Если установленная версия уже актуальна, появляется сообщение **«Уже установлена актуальная версия ZapretMac»**. Предварительные релизы и понижение версии не устанавливаются.

Для перехода с 1.1.4 и более ранних версий сначала скачайте новый ZIP и запустите **install.command из новой папки**. Старый install.command устанавливает файлы из своей папки и не скачивает последнюю версию. Если GitHub недоступен, обновление из меню сообщает об ошибке; установленная программа продолжает работать до начала установки. Закройте Discord через **⌘Q** перед обновлением и откройте после завершения.

Установка через Git:

```bash
git clone https://github.com/Owl170/zapret-mac.git
cd zapret-mac
bash install.command
```

## Основное меню

Откройте **service.command**:

| Пункт | Действие |
| --- | --- |
| **1** | Подключить / перезапустить. Использует сохранённую подтверждённую стратегию; если её ещё нет, запускает автоподбор. |
| **2** | Остановить обход. При включённом автозапуске он снова запустится после перезагрузки Mac. |
| **3** | Заново автоматически подобрать TCP-стратегию. |
| **4** | Открыть режим голоса Discord. |
| **5** | Автоматически закрыть Discord и фоновые процессы, затем очистить кэш с резервными копиями. |
| **6** | Проверить подключение: состояние сервиса и результат каждого TCP/TLS-адреса. |
| **7** | Включить или отключить автозапуск. Отключение также останавливает обход. |
| **8** | Обновить установленный ZapretMac до последнего стабильного релиза GitHub. |
| **0** | Закрыть меню. Работающий обход продолжает работать. |

Настройки Game Filter, IPSet, QUIC, hosts и служебные действия убраны из меню. Старые настройки сохраняются при обновлении; совместимые команды Terminal оставлены для поддержки.

## Как работает автоподбор

Профиль может быть выбран только при успешных TCP/TLS-ответах от **DiscordMain, DiscordGateway, DiscordCDN и DiscordUpdates**, полной загрузке **страницы /app и одного JavaScript**, корректном ответе **публичного API** и получении **WebSocket Hello**. Дополнительно проверяются ответы **API обновления клиента Mac**, **актуального манифеста** и чтение **первых 1024 байт обоих файлов обновления** с CDN. Проверки рассчитаны на стабильный Discord, не используют токен аккаунта и не устанавливают обновления. Среди подходящих профилей предпочтение получает тот, у которого больше ответов YouTube, затем больше ответов всего. При равенстве сохраняется предпочтение текущему профилю. Перед сохранением повторяются все проверки. Подтверждения старой версии автоматически перепроверяются.

Если ни один профиль не прошёл все проверки, программа сообщает об этом и восстанавливает прежние настройки и состояние сервиса. Установка при этом сохраняет автозапуск по выбранной настройке. Отчёт `auto-strategy-*.json` лежит в `/Library/Application Support/ZapretMac/logs`.

Если профили подтверждают базовый TLS, но **DiscordApp** не загружается, подбор дополнительно проверяет до шести текущих IPv4-адресов `discord.com`, полученных через [DNS-over-HTTPS Google](https://developers.google.com/speed/public-dns/docs/doh/json), на трёх наиболее успешных профилях. IP не вшиты в программу. Сначала через каждый адрес полностью загружаются /app и один JavaScript с исходными Host/SNI и проверкой сертификата. Только после успеха создаётся отдельный блок **DISCORD ENDPOINT ZAPRETMAC** для одного `discord.com` в `/etc/hosts`, очищается кеш DNS и **дважды повторяются все проверки Discord**. При отказе, прерывании или ошибке сохранения отчёта блок откатывается. Ваши записи `discord.com` и записи Flowseal автоматически не заменяются; другие домены и настройки DNS/IPv6 не меняются. Резервная копия лежит в `backups/discord-hosts-*`, результат — в `endpoint_recovery` отчёта подбора. Удаление программы через uninstall.command удаляет этот блок. Если сохранённый адрес перестал работать, пункт 1 запускает новый подбор, который может заменить его после подтверждения нового адреса.

Автоподбор выполняется при установке и по пункту **3**. Пункт **1** перепроверяет сохранённую стратегию в текущей сети; без подтверждения или при отказе запускает новый подбор. При каждой загрузке Mac перебор не повторяется. Если сменился провайдер или Discord снова перестал подключаться, запустите пункт **3**. Перебор перезапускает обход и прерывает текущие соединения: после него переподключите приложения. При сообщении «Ни один профиль…» прежние настройки восстанавливаются: показанная после этого стратегия не является успешно подобранной.

При **Checking for updates** выполните **3**, затем полностью перезапустите Discord. **6 — «Проверить подключение» находится в основном меню service.command**, а не в меню голоса. HTTP 404 на корне шлюза и HTTP 403 на корне CDN подтверждают только TLS-соединение. HTTP 200 с последующим таймаутом означает незавершённую загрузку. Для DiscordApp, DiscordScript, DiscordAPI, DiscordWebSocket, DiscordUpdateAPI, DiscordUpdateManifest и DiscordUpdateDownload требуется «Проверка пройдена». Чтение начала файла не подтверждает полную загрузку, проверку хеша или установку обновления. Вход в аккаунт, остальные ресурсы приложения, видео и звук проверяются в Discord.

При таймаутах Discord пункт **6** дополнительно сравнивает TLS через **IPv4 и IPv6**, показывает записи Discord из `/etc/hosts` и сохраняет `logs/connection-*.json`. Правила, DNS и hosts при диагностике не меняются. Передайте этот отчёт вместе с итогом автоподбора и результатом открытия `https://discord.com/app` в браузере на том же Mac. Очистка кэша не исправляет недоступный сетевой адрес; состояние «Сервис: ЗАПУЩЕН» означает работу процессов.

В наборе 12 TCP-профилей. Кроме прежних восьми, автоподбор испытывает **tlsrec-first** (граница TLS после первого байта ClientHello), **tlsrec-sni** (внутри расширения SNI), **tlsrec-host** (после первого символа имени) и **split-sni** (четыре TCP-разбиения вокруг SNI). Поддержка параметров и правильная передача TLS проверяются на macOS; работоспособность против DPI конкретного провайдера определяется результатом подбора.

При частичном отказе, например успешном API и таймауте DiscordApp, диагностика также выполняется. Строки **DiscordAppIPv4 / DiscordScriptIPv4 / DiscordAppIPv6 / DiscordScriptIPv6** проверяют полную страницу и один JavaScript с тем же Python/TLS, что основные проверки, и показывают адреса попыток подключения. Имя SNI и проверка сертификатов сохраняются; результаты не входят в оценку кандидатов и не меняют семейство адресов приложения. Если для домена нет AAAA-записи или маршрута IPv6, его отказ сам по себе не означает неисправность IPv4.

Адреса `::ffff:IPv4`, которые может вернуть macOS, теперь исключаются из проверки нативного IPv6. При полученных HTTP-заголовках и остановке тела ответа строка сохраняет HTTP-код и количество прочитанных байт, но **не подтверждает загрузку**.

## Очистка кэша Discord

Выберите **5** в основном меню. Программа автоматически завершит Discord, Canary, PTB и их фоновые процессы в вашей учётной записи, дождётся остановки и затем переместит существующие папки кэша в резервные копии. Текущий звонок Discord завершится. Вручную нажимать **⌘Q** не требуется; после очистки откройте Discord снова.

Если процесс не завершился после обычного сигнала, программа принудительно завершит оставшиеся подтверждённые процессы Discord. При ошибке определения процесса или неудачной остановке очистка не начинается. Если Discord повторно запущен во время переноса, перенос прерывается и уже перемещённые папки восстанавливаются. Остановка и очистка выполняются с правами вашей учётной записи.

Для каждого из трёх клиентов проверяются `Cache`, `Code Cache`, `GPUCache`, `DawnCache`, `DawnGraphiteCache`, `DawnWebGPUCache`, `ShaderCache`, `GrShaderCache`, `Service Worker/CacheStorage` и `Service Worker/ScriptCache`. Отсутствующие папки допустимы. Cookies, Local Storage, IndexedDB и настройки аккаунта сохраняются. Символические ссылки пропускаются.

Копии имеют суффикс `.zapret-backup-*` и находятся рядом с исходными папками в `~/Library/Application Support/discord`, `discordcanary` или `discordptb`. На следующем запуске приложение создаёт свежий кэш. **Место на диске этим действием не освобождается**: старые данные остаются в копиях. Если Discord работает нормально, ненужные резервные папки можно удалить вручную.

При обычной ошибке или прерывании программа возвращает уже перемещённые папки. Если Discord успел создать новый кэш, он не перезаписывается; старая копия сохраняется, а программа сообщает об ошибке восстановления. Принудительное завершение процесса или отключение питания не позволяют выполнить откат.

## Голос Discord

Откройте **voice.command** или пункт **4** основного меню. Выберите **1 — Включить / перезапустить**, дождитесь UDP-самопроверки и переподключитесь к голосовому каналу.

По умолчанию используется `fake`. Пункт **5 — Помощник подбора голоса** последовательно проверяет relay/fake/ttl3/ttl5/ttl7/ttl9. Профиль сохраняется после вашего подтверждения слышимого звука в обе стороны. TCP-автоподбор не может подтвердить работу микрофона или приёма звука.

IPv4 и IPv6 проверяются отдельно. Неудачная IPv6-проба отключает только его UDP-правила. Если IPv4-проба не проходит или relay завершается, UDP-перехват снимается. Подробности и наблюдение при пропадании звука — в [VOICE.md](VOICE.md).

## Обновление и удаление

Скачайте новый архив и повторно откройте **install.command**. При установке через Git:

```bash
git pull --ff-only
bash install.command
```

Настройки, пользовательские списки и отключение автозапуска сохраняются. Установщик повторяет TCP-автоподбор. Для удаления движка и автозапуска откройте **uninstall.command**; настройки и отчёты остаются в каталоге установки.

## Совместимость и отчёты

VPN, Internet Sharing, нестандартные PF-правила и системные прокси могут менять путь трафика. Программа проверяет системные PF-hooks, не редактирует `/etc/pf.conf` и снимает только собственные правила и токен PF. Для перехвата нужны права администратора; запросы root исключены, сетевые проверки выполняются от пользователя установки. DNS браузера не меняет DNS приложения Discord.

Логи и отчёты находятся в `/Library/Application Support/ZapretMac/logs`: `service.log`, `udp.log`, `auto-strategy-*.json` и `voice-*.json`. Отчёты не записывают звук или данные аккаунта. Пользовательские списки лежат в `/Library/Application Support/ZapretMac/lists`; по одному домену/IP/CIDR в строке, комментарии начинаются с `#`. После изменения списков перезапустите обход пунктом **1**.

Для поддержки доступны команды:

```bash
sudo /usr/bin/python3 "/Library/Application Support/ZapretMac/zapret.py" diagnostics
sudo /usr/bin/python3 "/Library/Application Support/ZapretMac/zapret.py" auto-strategy
```

## Проверка исходников

В [проверке текущего изменения](https://github.com/Owl170/zapret-mac/actions/runs/37817812403) на macOS 14 и 15 прошли по 226 Python-тестов без пропусков и все нативные проверки ниже. Подтверждён полный UDP-путь IPv4; IPv6 отключился после ошибки маршрута. Реальный звонок в сети пользователя этими проверками не подтверждается.

Контроллер использует только стандартную библиотеку Python. Исходники движка включены, их версия зафиксирована в `PROVENANCE.json`; в установщике нет загрузки исполняемого кода из сети.

```bash
python3 -m unittest discover -s tests -v
make -C engine/tpws mac CC=clang CFLAGS='-std=gnu99 -Os -ffunction-sections -fdata-sections' LDFLAGS=''
sudo python3 scripts/check_native.py engine/tpws/tpws
sudo python3 scripts/check_engine_transport.py engine/tpws/tpws
sudo python3 scripts/check_pf_udp.py
```

`check_native.py` проверяет 100 комбинаций стратегии/фильтров и 16 PF-конфигураций с `--dry-run`/`pfctl -n`, без применения правил; также проверяет принадлежность порта 988 запущенному движку. `check_engine_transport.py` требует остановить ZapretMac и передаёт HTTP/TLS через каждый TCP-профиль, используя локальный сервер и временный PF-anchor только для зарезервированного адреса. Защита SOCKS от локальных назначений сохраняется. `check_pf_udp.py` также требует остановить ZapretMac и применяет временные UDP-правила только для зарезервированных тестовых адресов; проверяет перехват, NAT lookup и обратный ответ. Обе сетевые проверки снимают собственные правила и свой токен PF. В CI дополнительно собираются варианты движка и парсеров с AddressSanitizer/UndefinedBehaviorSanitizer. Эти проверки включены в [macOS CI](https://github.com/Owl170/zapret-mac/actions/workflows/macos-check.yml); точный результат смотрите для соответствующего коммита. После них для подтверждения обхода всё равно нужен реальный звонок на Mac в сети с соответствующими блокировками.

## Автоматические версии и релизы

Подключено расширение GitHub Actions [GitHub Tag Action](https://github.com/mathieudutour/github-tag-action). Workflow [Automatic version and release](.github/workflows/release.yml) запускается после каждого push в `main`:

1. Выполняет обязательную проверку macOS: тесты Python, универсальную сборку, проверки парсеров и HTTP/TLS под sanitizers, PF и UDP. Затем выполняет тесты Python на Ubuntu.
2. Рассчитывает следующую версию по сообщениям коммитов: `fix: ...` повышает patch, `feat: ...` — minor, `feat!: ...` или `BREAKING CHANGE:` — major. Для остальных изменений по умолчанию повышается patch.
3. Обновляет `VERSION`, строки текущей версии в README и VOICE.md, а также версию и контрольные суммы в `PROVENANCE.json`.
4. Собирает и проверяет ZIP, затем сохраняет изменения коммитом бота, создаёт тег `vX.Y.Z` на этом коммите и публикует GitHub Release с ZIP и SHA256.

Установленная программа читает номер из `VERSION`; вручную менять номер в Python-коде не требуется. Первоначальный тег `v0.2.0` публикуется без дополнительного повышения версии. Повтор после прерывания публикации продолжает согласованный коммит версии без нового повышения номера. Повторный запуск того же отмеченного тегом коммита обновляет его архив, сохраняя номер. Теги существующих версий не перемещаются.

Workflow использует встроенный `GITHUB_TOKEN` с правом `contents: write`. Дополнительные токены или платная подписка на расширение не требуются. Для ветки `main` с запретом прямой записи бота потребуется адаптация workflow под правила репозитория. Результат можно проверить на вкладке [Actions](https://github.com/Owl170/zapret-mac/actions).
