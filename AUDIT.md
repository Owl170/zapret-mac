# Аудит ZapretMac — 8 октября 2026

Проверены контроллер, UDP-relay, управление PF, установщик, восстановление настроек, упаковка и workflows GitHub. Исходники стороннего `tpws` сохранены; проверены его сборка, используемые параметры и защита от соединения с собственным портом. Это отчёт о найденных дефектах и выполненных проверках, а не гарантия отсутствия всех возможных ошибок.

## Исправленные дефекты

| Приоритет | Сбой до исправления | Исправление и проверка |
| --- | --- | --- |
| P1 | Ошибка снятия одного PF-anchor или записи статуса прерывала очистку остальных ресурсов. Могли оставаться перенаправления и дочерние процессы. | Независимые действия cleanup, проверка кода возврата PF, ограниченное ожидание процессов, обработка гонки завершения. Токен PF сохраняется при неудачном освобождении; ошибка его первоначальной записи освобождает полученную ссылку PF. |
| P1 | Установщик от root мог следовать symlink/hardlink назначения и перезаписывать внешний файл. | Проверка ссылок и владельца/прав каталогов, атомарная замена файлов. Регрессии проверяют сохранность внешнего файла. На macOS-раннере родитель установки имеет `uid=0`, `gid=80`, режим `0755`. |
| P1 | Ошибка посередине обновления оставляла разные версии модулей и движка. | Проверка новой конфигурации и снимка бинарника до остановки; откат прежних файлов и удаление новых при ошибке. Прежний работающий сервис запускается после успешного отката. |
| P1 | Успешная IPv4-проба отменялась из-за последующего отказа IPv6, хотя IPv4-транспорт был исправен. | Отдельные проверки семейств. При ошибке IPv6 удаляются все его UDP-правила, а проверенный IPv4 сохраняется. Непроверенный IPv6 не включается. |
| P1 | Прямые локальные пакеты без NAT-состояния могли завершать весь UDP-relay. | Такие пакеты отбрасываются; `ENOENT` не останавливает исправный relay. Неоднозначные записи и повторные структурные ошибки PF по-прежнему отключают перехват. |
| P1 | После `kill -9` ручного supervisor оставшиеся процессы занимали порты следующего запуска. | Сохранённые PID проверяются по пользователю root и команде перед завершением. Проверены повторное использование PID, живой supervisor и смена интерпретатора. Процессы не ищутся по занятым портам. |
| P1 | Упаковщик допускал дополнительные файлы без SHA256, пути вне пакета и ссылки на внешние файлы. | Manifest должен покрывать весь состав ZIP; проверяются типы файлов и ссылки. Архив использует тот же снимок байтов, который проверен по контрольным суммам. |
| P2 | Ошибки остановки или записи отчёта оставляли выбранный пробный профиль вместо прежних настроек. | Настройки и прежний сервис восстанавливаются независимо от записи CSV/JSON. Проверены прерывание подбора и ошибки файловой системы. |
| P2 | Ошибка чтения TTL теряла настоящий UDP-пакет; ошибка записи статуса могла оставлять сокеты открытыми. | Фейки остаются необязательными, настоящий пакет передаётся при неудаче чтения TTL. Сокеты закрываются в независимом cleanup. |
| P2 | Ошибка записи версии/ZIP или прерывание сразу после rename оставляли частично обновлённые файлы. | Подготовка всех файлов до замены и откат при ошибке/KeyboardInterrupt. Тег создаётся после успешной упаковки. Порядок ZIP одинаков на Windows и Unix; известные результаты локальной сборки исключены. |
| P2 | Проверка ABI через `assert` исчезала при оптимизированном запуске Python. | Явная проверка с ненулевым кодом завершения; регрессия запускает проверку с `python -O`. |
| P2 | Неполные маркеры блока hosts могли остаться незамеченными, после чего добавлялся второй блок. | Требуются отдельные строки обоих маркеров. Повреждённый блок отклоняется; проверено удаление корректного блока без финального перевода строки. |

Дополнительно проверяются типы JSON-конфигураций, статусов и UID пользователя установки. Ошибки дают понятное сообщение вместо необработанного исключения.

## Результат нативной диагностики UDP

В [проверке macOS](https://github.com/Owl170/zapret-mac/actions/runs/37694797360) прошли 105 Python-тестов, универсальная сборка для arm64/x86_64, 100 конфигураций движка, 16 вариантов PF и сравнение ABI. IPv4-проба прошла полный путь с проверкой точного ответа. Захват заголовков показал исходящий пакет и обратный ответ после NAT на `lo0`; на `en0` эти пакеты не выходили.

Следующая IPv6-проба завершилась в `socket.connect()` с `errno=65`, `No route to host`, для `2001:db8::feed`. Наличие IPv6 default route само по себе не подтвердило доступность тестового адреса. Это объясняет прежний общий отказ UDP; сообщения о таймауте IPv4 в ранней документации были неточными.

В исправленной реализации этот отказ отключает только UDP-перехват IPv6. Проверенный IPv4 остаётся активным; его подтверждение всё равно обязательно. Если завершается сам relay, снимаются правила обоих семейств.

Диагностика включается командой `sudo python3 scripts/check_pf_udp.py --trace` при остановленном ZapretMac. Она ограничена заголовками тестового UDP и этапами сокета; токен пробы, содержимое пакетов и звук не печатаются.

## Границы проверки

- Реальный двусторонний звонок Discord в сети с блокировкой пока не выполнен. Локальная PF-проба подтверждает транспорт, а не обход конкретного DPI или слышимый звук.
- UDP-путь IPv6 нельзя считать проверенным на раннере с неудачной IPv6-пробой.
- Один клиентский UDP-сокет с несколькими адресами назначения может создавать неоднозначные записи PF. `E2BIG` прекращает перехват, чтобы не угадывать адрес; совместимость такого WebRTC-сценария требует отдельной проверки.
- Активный `set skip on lo0` при уже загруженных стандартных hooks пока не определяется отдельной проверкой. Проверка файла `pf.conf` действует при загрузке системной конфигурации; нестандартный активный PF требует проверки на Mac.
- Cleanup не может выполниться внутри процесса, завершённого `kill -9`. Следующий запуск восстанавливает сохранённые процессы, но узкое окно между созданием процесса и записью его PID остаётся: незаписанные PID не угадываются. Откат нескольких файлов также не является атомарной транзакцией при отключении питания; ошибка самого отката сообщается отдельно.
- SHA256 проверяет согласованность содержимого пакета с manifest и не заменяет цифровую подпись издателя.

Регрессии находятся в `tests/test_controller_audit.py`, `test_udp_audit.py`, `test_packaging_audit.py`, `test_native_audit.py` и `test_hosts_audit.py`; прежние тесты также сохранены.
